# 新增计分题（能力题）写作说明（中文版）

HumanBench「你是几B的模型？」里，能力题决定玩家的跑分表、参数量和“已知问题”。这次给 6 个题池各加 6 道，**写入 `i18n/new/zh_ability_add.js`**，格式：

```js
const NEW_ABILITY = {
  dense: [ q, q, q, q, q, q ],
  cursor: [ … ], terminal: [ … ], automation: [ … ], frontier: [ … ], gdpval: [ … ],
};
```

## 先看
- `bank.js` 里 `POOLS` 这 6 个题池的现有题目（格式、口吻、难度），**照抄对象结构**：`{ lv, q, issue, opts: [{ t, ok, r }, …] }`，可选 `term`（终端命令）、`code`（代码/配置）、`u`（角色扮演开场，一般不用）、`half`（诚实“我不知道”给半分）、`fun`（整活选项给半分）、`halluc`（答错算幻觉）。
- `i18n/new/EXISTING_ABILITY.md`：这 6 个题池已有题目的题干，不要重复。
- 题池含义：dense = “同时回答”跨领域两小问（① ②，考切换）；cursor = AI 写代码场景里的判断；terminal = 终端命令/报错；automation = 自动化、cron、正则、脚本、表格公式；frontier = 前沿 AI 常识与行业现象；gdpval = 职场实务（邮件、表格、汇报、合同、会议）。

## 规则
- 每题 4 个选项，恰好 1 个 `ok: 1`；可以有 1 个 `fun: 1` 整活选项或 `half: 1` 的诚实选项。
- **正确选项不能是唯一最长的选项**（按字数）。错误选项要“听起来很有道理”。
- 事实必须准确；数字、命令、公式要自己算一遍、过一遍。拿不准的不写。
- 难度 `lv`：每个题池 6 道里大约 lv1 ×1、lv2 ×3、lv3 ×2（这些题池现在 lv1 偏多）。不要写 lv4。
- 每题 `issue` 是一句“已知问题”，会印在分享卡上（如“看不出命令里的致命空格”），要短、具体、好笑。
- `r` 是选后点评：答对讲清原理，答错指出错在哪，短而有梗。
- 不用 emoji。口吻像中文网友，整活但不油。尽量能翻译（别整道题只靠中文谐音）。

## 自检
`node qa/ability_check.cjs` 必须 OK（结构、ok 唯一、最长项、lv、字段）。最后回报 5 行以内。
