# HumanBench 新增内容写作说明（中文版）

「你是几B的模型？」是整活测评：玩家扮演 AI，选 AI 会怎么回。结果页的分享卡会引用玩家选过的原话（人格卡）、名场面对话的结局（名场面卡）。这次要把三类内容翻倍，**目的是让不同玩家的分享卡不撞车**，所以每道题都要有辨识度、选项原话要有梗、结局标题要值得截图。

先读：
- `i18n/new/EXISTING.md`：已有内容，不要重复这些梗/场景
- `i18n/new/RESEARCH.md`：最新 AI 圈梗和真实事件（可用素材；用真实事件时年份和细节要准，不确定的不要写成事实）
- 格式范例：`chats.js`（CHATS）和 `bank.js` 里的 `PERSONA_Q`、`SLOP_VIBES`，**照抄它们的对象结构**

## 通用规则
- **不点名普通人**：真实事件里的受害者、维护者、网友一律泛称（“某开源维护者”“一位用户”）；公众人物和公司可以提，但不嘲讽个人、不编造其言行。太黑的事件（勒索、造假账号、恶意代码）要轻处理，只取“AI 很离谱”的一面，别写成教程。
- 做成“你来当 AI”：用户发消息，玩家选 AI 怎么回。不要做“某年某模型干了啥”的知识问答，也不要“这话像谁说的”。
- 不用 emoji；不要对错标记（这些题没有标准答案）。
- 手机上看：用户消息 u ≤ 60 字；选项 t ≤ 40 字；reply ≤ 40 字；结局正文 ≤ 50 字；结局标题 2–7 个字。
- 口吻像中文网友，短、准、狠。模型口癖用各家最典型的说法（Claude「你说得对」、4o「我接住你了」、Codex「先给结论/质量门禁/commit SHA」、DeepSeek 思考流跑偏、豆包嘴甜秒认错、Gemini 夸你洞察力、Grok 嘴欠、Kimi 超长）。
- 尽量能翻译：可以用中文网络梗，但别让整道题只靠中文谐音成立（翻译时要能换成当地等价梗）。
- 标签 `tr` 只能用：syc 谄媚、preach 说教、verbose 话痨、jail 被越狱、hall 一本正经编、chaos 整活、based 清醒、stub 嘴硬、warm 暖心、nerd 理工脑、deaf 不听指令。「清醒」和「嘴硬」是两回事。每个选项 0–2 个标签。
- 模型口味 `id`（选中会给该模型加“AI 味”）只能用："Claude"、"GPT-4o"、"Codex"、"GPT-5 系"、"ChatGPT"、"DeepSeek"、"Gemini"、"豆包"、"Kimi"、"Grok"。大约三分之一的选项带 id，**只有真的像那家的招牌说法才带**。
- 人格轴 `ax`（0 = 左端，100 = 右端）：W 回应重心（解决问题 / 先接情绪）、D 输出密度（压缩结论 / 充分展开）、V 行动节奏（先试一版 / 先行验证）、T 表达锋芒（温和铺垫 / 直接点题）、X 思路展开（聚焦收束 / 联想发散）、C 协作方式（自主推进 / 边聊边对齐）。
- `think`（深度思考流）可以放，但每道题最多一两个选项，且要短（≤ 80 字）、要好笑。
- 结局 `E("标题", "一句话点评", 可选 id)`：标题是分享卡上的“名场面”，要一眼好笑；点评一句话收住。涉及真实事件的，点评里写清年份和出处类型（如“2025 年真有……”）。

## 三类内容

### A. 名场面对话（新增 15 段）→ `i18n/new/zh_chats_add.js`
```js
const NEW_CHATS = [
  { title: "…", scene: "时间或地点 · 身份", u: "用户第一句", opts: [ … ], nodes: { a1: [ … ], a2: [ … ] } },
  …
];
```
- **要短**：开场 3 个选项 → 每个进一个节点（节点 2–3 个选项，都是结局）。总共最多两层，不要三层（线上数据：长对话劝退人）。
- 每段 6–9 个结局，结局标题都不同。
- 素材优先用 RESEARCH.md 里的真实梗/事件，也可以原创情境（AI 在职场、恋爱、客服、编程、家庭群里整活）。
- 开场选项里通常有一个“清醒”的正常回答、一个名场面复刻、一个整活。

### B. 人格小对话（新增 12 道，每个轴 2 道）→ `i18n/new/zh_persona_add.js`
```js
const NEW_PERSONA = { W: [q, q], D: [q, q], V: [q, q], T: [q, q], X: [q, q], C: [q, q] };
```
- 结构同 PERSONA_Q：生活/工作/学习/感情里的日常场景（不聊 AI），选项的 `ax` 主要落在本轴，两端都要有（至少一个接近 0、一个接近 100），可以顺带别的轴。
- 开场 3–4 个选项，每个 go 到节点，节点 2–3 个结局。
- 选项原话会被引用到分享卡上（“因为我说过：……”），要像人会截图的一句话。

### C. AI 味现场（新增 6 道）→ `i18n/new/zh_slop_add.js`
```js
const NEW_SLOP = [ { u: "用户一句日常话", opts: [ { t, c, tr, id }, … ] }, … ];
```
- 结构同 SLOP_VIBES：4–5 个选项，其中 3–4 个是不同模型的典型“AI 味”回复（带 id），1 个是干净利落的人话（tr: ["based"]，不带 id）。`c` 是一句吐槽点评。
- 场景是用户随口一句话（改个日期、说句谢谢、问个小事），AI 却把它变成了自家招牌表演。

## 自检
写完运行：`node qa/new_check.cjs <chats|persona|slop>`，必须显示 `OK`（结构、标签、轴、id、节点可达、字数）。不通过就改到通过。

最后回报 5 行以内：写了几道、用了哪些真实梗、自检结果。不要贴全文。
